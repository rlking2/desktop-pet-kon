## 〇、机制速览（人家已经实现的）

```
素材组名       触发器                          优先级   循环               现在是什么
------------------------------------------------------------------------------------
idle          默认 / 其他动作播完回到它        0       是                 1 张定格图（只有人物）
happy         右键菜单"开心（保持动作）"       1       **是（保持住，再点一次才退出）**  3 帧动画（带彩纸）
angry         右键菜单"生气" / 台词             2       否                 （没有素材，走 CSS）
pet   (或 pat) 右键菜单"摸头"                  3       否                 interact 组 3 帧
```

- **高优先级能打断低优先级**；低优先级**不能**打断正在播的高优先级（避免动作打架）
- **单次动作播完自动回待机**（唯一的例外见下面的「保持动作」）
- **某组素材缺失时自动退回 CSS 形变动画**（所以主人可以只画 idle，其余照样有反馈）
- 组名别名：`happy`/`hop`、`pet`/`pat` 都可以，程序会按顺序找
- **保持动作（`poseHold`，主人 2026-09-24 的要求）**：「开心」是**开关** ——
  点一次就把该组**用 `loop` 循环播**（单帧素材 = 定格住，多帧素材 = 一直播），
  并且挡住"回待机"和"鼠标靠近"这两条自动切动作的路径，直到**再点一次**同一个菜单项。
  菜单项是 `checkbox`，勾选状态由渲染层 `reportPose()` 回报（渲染层才是真状态）。
- 「开心」**优先**播 `happy` 组；没有这个组才退回 `interact`，再没有才只用 CSS（后两者不保持）

### 主人 2026-09-24 的对调：待机 ↔ 开心

| | 之前 | 现在 |
|---|---|---|
| **待机** | 3 帧动画（带彩纸、会动） | **1 张定格图**（主人挑的姿势，**只有人物**，静） |
| **开心** | 1 张定格图（主人给的姿势图） | **3 帧动画**（原来待机那三帧，**带彩纸**，循环播） |

理由（人家理解的）：**静止的图不该配"冻住的彩纸"**（点「开心」保持时，一堆彩纸僵在那儿很怪），
而**动着的动画配彩纸才好看**。所以彩纸跟着"会动的三帧"去了「开心」，
「待机」换成了干干净净只有人物的那张定格图。

### 描边（sticker outline）——**当前：按部件描边，可在面板里实时调**

> 主人 2026-09-24 的最终要求：**「头发，眉毛，手，裙子只勾最外层，腿和脚」**
> \+「勾线的**粗细**、**黑白深浅**两项同之前调播放速度一样给我两条横条」。

两层结构（都在 `renderer/renderer.js` 里画，不烘进素材）：

| 层 | 怎么来的 |
|---|---|
| **部件线** | 离线掩码 `assets/build/edges/<组>/<帧>.png`（`node scripts/make-edge-masks.js` 生成）：按颜色把画面切成"部件区域"，只在**跨部件**的交界画线。**同一色系内部不画**（头发内部深浅花纹）、**「深色↔白色」不画**（裙子黑白条纹 → 于是"裙子只勾最外层"自动成立）、**隔着原画细线相邻的部件也算相邻**（拿线当桥） |
| ⚠️ 判据里的四条硬规矩 | ① `hair` 要够宽（受光金/背光棕/偏橄榄的暗色**同属一个色系**，否则头发内部会被描）② `dark` 要**排除暖色**（否则头发暗部与亮部成了跨色系）③ **深色那一侧必须成块**（填充率 ≥ 0.3；原画的细笔触/发丝线不算部件）④ 同色系例外**只给 dark↔dark**（黑手套 vs 黑裙子），别扩大到头发 —— 这四条都是"开心第三帧图线过厚且割裂"那个 bug 换来的（见 devlog/round-21.md） |
| **外轮廓** | alpha 形状往外扩一圈（每帧自动都有；彩纸也会被描 —— 因为它们在整帧 alpha 里） |

**两条横条（调试用，已按主人要求拆除）**：数值在 2026-09-24 调好并**固化**在
`renderer.js` 顶部的 `OUTLINE` 里 —— 主人试出的是 **粗细 0.25px、深浅 62%（线色 `rgb(97,97,97)`）**。
面板里那两条横条和 `__petTest.setOutline` 都已删除（跟当初调速滑条一个流程）；
以后要再调，见 `devlog/round-23.md` 里的加回步骤，或直接用
`node scripts/preview-compose.js idle --width=0.25 --depth=62` 离线看效果。

| 参数 | 值 | 作用 |
|---|---|---|
| `OUTLINE.width` | **0.25 px** | 部件线 + 外轮廓的粗细（一个值管两处）；**0 = 不描边** |
| `OUTLINE.depth` | **62** | 线色深浅：0=纯白 → 100=纯黑（62 → `rgb(97,97,97)`） |

**不描的区域**（主人指出来的）：`OUTLINE_EXCLUDE`（`renderer.js` 里，归一化矩形）——
靠近动作里那片"白蝴蝶"（压在脸上的白叶子）不描；要挖别的地方照格式加一行。

**当前还差一处**：手与**黑裙子**的交界没描（两者都是黑的，按颜色分不开；中间那条原画轮廓线
会被分割算法和周围黑块合并）。手与脸/头发的交界是描了的。要补的话用"手工补描区域表"最稳。

调参工具（都不用跑 Electron，几秒一轮）：
`node scripts/make-edge-masks.js --preview`（原图+红线对照）、
`node scripts/preview-compose.js idle frame-000 --width=1 --depth=20`（按屏上真实尺寸合成）。

自检：**2 条**（"参数已固化 0.25px/62%" + "调试横条已拆除"的反向断言）+ 掩码已接入 + 外轮廓像素取证。

## 二、逐条细化

### P0 `idle` 待机（必画）★

| 项目 | 值 |
|---|---|
| **触发条件** | 启动后一直循环；其他动作播完后回到它 |
| **循环** | 是（**当前只有 1 帧 → 看着就是静止的定格图**） |
| **当前素材** | `assets\idle\frame-01.png`（主人 2026-09-24 挑的姿势，**已"只留人物"**：彩纸/叶子/花瓣全清掉了） |
| **想做成动画** | 往 `assets\idle\` 多丢几帧（`frame-01/02/03…`）再跑一次素材构建即可，代码不用改 |
| **建议帧数** | **8 帧**（6~12 都行，想做呼吸感的话） |
| **单帧时长** | 204ms/帧（0.49× 固化速度） |
| **动画内容** | 身体上下起伏 2~4px、头发/尾鳍轻微摆动、偶尔眨眼 |
| **素材目录** | `assets\idle\` |

**眨眼怎么做更省事**：不用画进循环里。现在的代码是**每 4.6 秒眨一次**（独立定时），
主人可以在循环里加 1~2 帧"闭眼"，人家把眨眼改成随机触发某个帧号即可；也可以完全不画，人家用代码叠加眼皮。

### P1 `pet` 被摸头（建议）

| 项目 | 值 |
|---|---|
| **触发条件** | 右键菜单 → 摸头（这是最常被点的互动） |
| **循环** | 否，播一次 |
| **建议帧数** | **6 帧** |
| **时长** | 共约 700ms（约 120ms/帧） |
| **动画内容** | 缩一下脖子 → 眯眼 → 脸红加深 → 尾巴轻摆 |
| **素材目录** | `assets\pet\`（叫 `pat` 也行） |
| **不画的替代** | CSS 版：整体缩放 + 腮红透明度提升，效果可接受 |

### P2 `happy` 开心（**已接入素材**）

| 项目 | 值 |
|---|---|
| **触发条件** | 右键菜单 → 「开心（保持动作）」（**开关**：点一次开、再点一次关） |
| **循环** | **是** —— 这就是"保持"的实现（多帧素材 = 一直播，单帧素材 = 定格住） |
| **当前素材** | `assets\happy\frame-01~03.png`（**3 帧动画**，带彩纸 —— 就是原来待机那三帧，2026-09-24 与待机对调过来的） |
| **实际表现** | 点一次：切到开心的动画并**一直循环保持**（不会自己恢复）；再点一次：回待机。菜单项打勾 = 保持中 |
| **保持期间不受打扰** | 鼠标划过她身上不会切「靠近」动作；摸头/生气这类一次性动作播完也会**回到开心的动画** |
| **想换素材** | 丢图进 `assets\happy\`，跑 `node scripts\inspect-assets.js --write --normalize-height happy` |
| **不画素材时** | 退回 `interact` 组，再没有就只用 CSS：`translateY(-16px)` + 挤压拉伸（这两种都**不保持**，是一次性的） |
| **建议帧数** | **6 帧**（想做一段完整的"开心"小动画时） |

### P3 `angry` 生气（可选）

| 项目 | 值 |
|---|---|
| **触发条件** | 右键菜单 → 骂她"胖"（目前是菜单项，也可以做成彩蛋） |
| **循环** | 否，播一次 |
| **建议帧数** | **6 帧** |
| **时长** | 约 400ms × 3 次循环抖动 = 1.2s |
| **动画内容** | 鼓腮、眉毛压下、左右甩头、尾鳍炸开 |
| **不画的替代** | 现在的 CSS 版：左右位移 ±6px + 旋转 ±3° |

### P4 `sleep` 睡觉（可选，新功能）

| 项目 | 值 |
|---|---|
| **触发条件** | 无操作超过 5 分钟（需要人家新增逻辑） |
| **循环** | 是 |
| **建议帧数** | **6 帧** |
| **单帧时长** | 300ms/帧 → 一轮 1.8 秒（慢速） |
| **动画内容** | 坐下/趴下、闭眼、缓慢起伏、偶尔冒出 Z |
| **备注** | 这个动作的"进入/退出"最好有过渡帧，否则会瞬间变形 |

### P5 `drag` 被拎起来（可选）

| 项目 | 值 |
|---|---|
| **触发条件** | 按住鼠标拖动时（现在只改了鼠标指针形状） |
| **循环** | 是（拖动期间一直播） |
| **建议帧数** | **4 帧** |
| **动画内容** | 手脚垂下、尾巴晃、身体轻微摆荡 |

## 四、画图时的硬性要求（不满足会被体检拦下）

| 要求 | 为什么 |
|---|---|
| **PNG 带 alpha 通道（透明背景）** | 不然桌宠是一块方块，还会挡住鼠标穿透 |
| **背景必须抠干净** | 残留白底会被体检判为 FAIL |
| **各帧主体大小尽量一致** | 尺寸可以不同（程序会对齐），但**角色本身**忽大忽小会很怪 |
| **不要在帧里画投影/地面阴影** | 程序会给整个形象加统一投影，重复会显脏 |
| **建议画布 2 的幂或统一尺寸**（如 128×128 / 256×256） | 好管理，缩放不糊 |
| **角色居中留白，别贴边** | 程序按主体包围盒对齐，贴边容易切到 |

## 五、帧率要"感觉对"，建议主人先定这个

| 动作类型 | 常用帧率 | 单帧时长 |
|---|---|---|
| 慢速（睡觉、呼吸） | 4~6 fps | 170~250ms |
| 中速（待机、走路） | 8~10 fps | 100~125ms |
| 快速（蹦跳、生气） | 12~15 fps | 65~85ms |

> 现在程序里**所有动作统一 120ms/帧（≈8fps）**。逐帧动画的节奏感很吃帧率，
> 主人画完可以先跑起来看，觉得"太快/太慢"直接跟人家说，人家改清单里的 `delayMs` 就行，**不用重新导图**。

## 六、人家负责的技术部分（主人不用操心）

- 拆帧（精灵图 4×2 → 8 帧）/ 对齐（按主体包围盒消除"每帧抖动"）
- 每帧时长控制、循环与播完回待机
- 动作优先级：**摸头 > 生气 > 开心 > 待机**（同一次点击不会两个动作打架）
- 素材缺失时自动退回内置 SVG 形象，不会白屏
- 换素材后自动重算穿透掩码（否则点击判定范围会跟角色对不上）
