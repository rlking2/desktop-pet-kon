# 第 32 轮：她的话能走模型了 + 人格可调（但离线体验一个字不变）

主人这一轮的原话：

> **「改变输出语言，现在开心和摸头的语言是固定的，我想在不接入API的情况下不改变，在接入API后拥有更加丰富可以调整的性格和语言大模型」**

主人随后做了三个选择，人家按这三个选择定的范围：

| 选择项 | 主人选的是 | 人家的理解 |
|---|---|---|
| 范围 | **② 动作能走模型 + ③ 人格可调** | 不只是聊天那条路，动作台词也要能问模型；性格要在设置里能改 |
| 走模型的时机 | **开心开 / 开心关 / 生气 / 空闲主动开口** | **摸头不在其中** —— 摸头永远念本地台词 |
| 延迟策略 | **等模型说完再开口** | 动画**立刻**播；台词等主进程那一趟回来再显示 |

## ① 判定逻辑单独落一个纯模块：`lib/action-lines.js`

第 32 轮之前，五组台词**写死在渲染层**（`renderer.js` 的 `LINES`），主进程发 `pet:action`，
渲染层直接念本地那几句 —— **接上 API 之后她照样念写死的话**。

这轮要把"念哪句话"变成可配置的，涉及三方（渲染层、主进程、设置窗口），所以判定逻辑必须落在一个
**谁都依赖、但自己不依赖任何人**的纯模块里：

- 纯函数，**不碰 fs / 网络 / Electron** → 自检可以直接 `require` 它怼边界（不花 token、不用真机）；
- 台词表、人格五项字段、6 个预设、每个时机的提示词片段、气泡硬约束、空闲限频闸门
  `idleGate()` 的**唯一权威来源**都在这里；
- 渲染层只拿一小份投影（`LOCAL_LINES` / `ACTION_LABELS`），**不重复抄一遍**。

两条铁律写进了文件头注释：

1. **离线体验零变化** —— 没配 API、API 关了、模型失败、返回空 → 一律退回本地台词，**一个字都不改**
   （台词与第 32 轮之前 `renderer.js` 里那份**逐字一致**，不许顺手"优化"措辞）。
2. **失败绝不进气泡** —— 动作类走模型失败就**静默退回本地台词**、细节写日志。
   聊天那条路失败要说话（那是主人在主动问），动作这条路是她在反应，不该蹦英文报错。

## ② 配置：`api-config.js` 新增五个字段

| 字段 | 内容 |
|---|---|
| `persona` | 嵌套五项：`identity` / `style` / `quirks` / `taboos` / `examples` |

`save()` 从"整体覆盖"改成**嵌套对象逐层展开合并**（只改一格不会把别的格清空），
并新增导出 `reloadCache()`（见 ⑦ 的坑 2，它就是被这个坑逼出来的）。

## ③ 主进程：新通道与心跳

新增 IPC：`pet:action-line`（渲染层问"这一刻说哪句"）、`pet:debug-prompt`、`pet:user-active`、
`pet:toggle-mute`、`pet:mute-get`、`pet:idle-state`、`pet:idle-tick`；

人格五项 → `buildSystemPrompt()` → 人格块 → 气泡硬约束 → 时机提示；
动作类请求走 `buildActionMessages()`，**不带对话历史**（每次反应都是独立一句，
不把"开心"这类内部提示写进聊天历史；聊天那条路仍带历史）。
旧的「人设提示词」字段非空时**整块覆盖**人格设定，老配置不会因为这次升级失效。

## ⑥ 安全与限频：主动开口**必须**有闸门

| 项 | 值 / 做法 |
|---|---|
| 密钥 | 仍只由主进程读写 `%APPDATA%\dsh-desktop-pet\api-config.json`，渲染层只拿掩码；自检断言盯着"3032 字节的安全视图里找不到明文密钥" |
| 间隔 | 默认安静 **15 分钟**才可能开口一次（带 ±25% 抖动，免得像定时任务） |
| 每日上限 | 默认**每天最多 12 次** |
| 静音时段 | 默认 **23:00–08:00** 不主动开口 |
| 一键静音 | 右键「安静一会儿」——**只静音主动开口**，主人打字聊天不受影响 |
| 真实调用 | 自检里**一条真实 API 调用都没有**：走模型那条路靠 `mockReply` 旁路，同样跑完 `chat()` 整条链路，只是不发网络请求 |

## ⑦ 本轮真实踩到的 5 个坑（最有价值的部分）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 自检 `readFileSync(apiConfig.getConfigPath())` 直接崩（ENOENT） | 配置文件**只有 `save()` 才落盘**，只调 `load()` 时它**根本不存在** | 读不到就当空；收尾时把"不存在"这个状态也还原 |
| 2 | `apiConfig.save({})` **不重读磁盘**，把内存缓存原样写回去 → "改了配置"其实一个字没变，**13 条断言全红在同一个原因**（症状是 `api_not_ready`） | 缓存只在启动时读一次 | 新增并导出 `reloadCache()` |
| 3 | 注入了"现在几点"，却没注入"上次主人理她的时间" → `too_soon` 永远先把判定拦下，`daily_cap` / `quiet_hours` 根本轮不到 | 闸门是**短路**写法，先命中的先返回 | `idleTest` 增加 **`baselineMs`** 注入 |
| 4 | 每日上限断言换了注入日期 → 计数按**本地日期**归零，`daily_cap` 永远轮不到 | 两条断言用了两个不同的 `nowMs` | 与"该开口"那条断言**复用同一个 `nowMs`** |
| 5 | 自检的 `writeCfg` 从**块开头那份配置快照**展开 → 中间设的密钥被后一次覆盖回旧值，又一轮连环红 | 快照是旧的 | 每次都**从磁盘当前值出发**再改 |

## ⑧ 两处"改设计就得改断言"（不是 bug，但必须记）

- 新增菜单项让「菜单项符合本轮设计」的 `labels.length === 7`、`clickables === 6` 变红。
  改成**按菜单结构算**（标题项 vs 可点击项），而不是写死数字 —— 写死数字的断言，
  每加一个菜单项就得回来改一次，那叫"断言绑住了设计"。
- 设置窗口原来的 `fitsNoScroll` 断言因为内容变高（**1905px 内容 / 724px 视口**）而
  **按新设计作废** —— 加了面板之后**滚动就是预期行为**，这条断言的前提没了。

> ⚠️ **必须坦白一处**：人家改菜单断言时，**第一版写出了一条恒真的废断言**
> （`clickables === ... + clickables*0 + ...`，右边恒等于左边）。自己当场发现并重写。
> 教训：断言写完要**心算一遍它在什么情况下会红** —— 想不出会红的情况，它就是废的。
