# 第 21 轮：修「开心」后面几帧图线过厚、跟前面割裂

主人的原话：**「开心动作后面几帧有bug，图线过厚且与前面的割裂」**。

## 一、先把"病根"量出来

「开心」是三帧动画（就是原来那三张待机图）。人家的掩码生成器会给每一帧单独算一遍部件线，
于是可以用**掩码像素数**横向比：

| 帧 | 修之前 | 修之后 |
|---|---|---|
| happy/frame-000 | 23 918 px | 26 224 px |
| happy/frame-001 | 17 755 px | 20 723 px |
| **happy/frame-002** | **41 542 px** ← 别人的 2 倍多 | **28 040 px** |

第三帧的掩码是另外两帧的两倍多 → 那一段自然"又粗又乱"，跟前两帧**完全不像** ✓ 和主人的描述对上了。

再把那一帧的掩码图放大看：**头发上被描了一堆又粗又断的线**（发丝线），前两帧几乎没有 →
一帧有、两帧没有 = 动画播起来"割裂"。

## 二、三个根因（一条条修）

| # | 根因 | 修法 |
|---|---|---|
| 1 | **"深色"色系太贪**：头发的暗部（124,113,95）被算成 `dark`，而头发的亮部是 `hair` → **同一块头发的亮部/暗部成了"跨色系"** → 整条刘海被描 | `dark` 判据加上"排除暖色"：`r>g>b 且 r-b≥15` 的算头发，不算 dark |
| 2 | **原画的细笔触被当成"部件"**：发丝线本身就是一笔深色，面积够大（≥900px）就被当成部件，于是"头发 ↔ 发丝线"成了合法的跨部件交界 | 加一条：**深色那一侧必须"成块"（填充率 ≥ 0.3）**；细长笔触填充率很低 → 不描 |
| 3 | **头发色系还是太窄**：印刷品扫描里头发有受光金 (196,172,133)、背光棕 (124,113,95)、偏橄榄的暗色 (128,131,84) —— 第三种被归到 `other`，于是"头发 ↔ 那块橄榄色"又被当成跨色系 | 把 `hair` 放宽成"`b<165` 且 `r≥b` 且 `g≥b` 且 110 ≤ 亮度 < 215" → 三种金色**同一色系** |

顺带把"同色系例外"**收窄到只给 dark↔dark**（黑手套 vs 黑裙子那种）——
之前它也可能放行"头发 ↔ 头发"的发丝线（人家试过：第三帧的刘海会被描满）。

## 三、验证

```
三帧掩码像素 26 224 / 20 723 / 28 040（原来 23 918 / 17 755 / 41 542）→ 三帧终于在一个量级
目视         合成到屏上尺寸：第三帧的头发干净了（只剩外轮廓和几笔该有的发际线），
             头发/手/裙子外层/腿脚都在；三帧看起来是同一个角色同一套线
自检         103/103 ✅
打包版自检   103/103 ✅
```

工具：`node scripts/make-edge-masks.js --preview`（出"原图+红线"对照图）就是人家逐帧比对的依据；
`node scripts/preview-compose.js happy`（按屏上真实尺寸合成）用来看"播起来像不像"。

## 改动文件

|---|---|
| `scripts/make-edge-masks.js` | `dark` 排除暖色；`hair` 放宽到三种金色；新增"深色必须成块"；同色系例外只给 dark↔dark |
| `assets/build/edges/**` | 8 张掩码全部重新生成 |
