# 第 27 轮：回复气泡贴回人物身边 + 「靠近」不恢复待机的 bug

主人两条反馈：

> **①「我让你自动识别对话框的位置，将回复框放在另一边，但你做的结果是直接将对话框放在了输入框的左边，已经脱离人物了，
>   希望回复框能在人物两边，而不是远离人物」**
> **②「鼠标靠近人物后如果在向下或向右移动，人物不会回归默认的待机动作需要修改」**

两条都是**上一轮（第 26 轮）自己引入的问题**，人家照实记下来。

## ① 气泡"脱离人物"：上一轮把窗口宽度写死了

第 26 轮为了"气泡不左右跳"，把两种状态的列钉成一样：`[气泡列][面板列][桌宠列]`（收起时面板列空着）。
结果收起态多出一条 **300px 的空面板列**，气泡虽然"挨着列"、但离人物整整 300px —— 主人看到的就是"脱离人物"。

**这一轮改回"两态列不同，但气泡列永远紧挨桌宠列"**：

| | 列布局 | 窗口宽 | 气泡离她多远 |
|---|---|---|---|
| 收起 | `[气泡列][桌宠列]` | 桌宠列 + 气泡列 ≈ 354 | 紧挨着（气泡右边界就在她左边界旁） |
| 展开 | `[气泡列][面板列][桌宠列]` | 再 + 面板列 300 ≈ 655 | 一样紧挨着（面板插在她和气泡之间的**外侧**？不，插在中间） |

⚠️ 等等，展开态面板插在中间的话，气泡不就被面板"顶开"了吗？—— 实际上**没有**：
面板列插在**气泡列和桌宠列之间**，气泡仍然贴着她那一侧，只是中间多了一块面板。
主人要的"回复在人物两边、不远离人物"就是这个效果（截图 `artifacts/shot-chat-split.png`：
气泡在左、面板在中、人物在右，三者紧邻）。

### 顺手挖出的一个真 bug：人物被挤出了自己的窗口

改宽度时人家第一版把 `closedWidth()` 写成 `Math.max(桌宠列, 气泡列)`（想"至少要装下最宽的那一个"）。
后果：窗口 188px 宽，而桌宠列在 `[86, 253]` → **人物有一半在窗口外**（点击也点不到），
连带"靠近"判定、命中区全都错位。自检里那条"人物被裁掉"的观测（`pet=[86,50,253,250] scene=0,0,188,250`）就是它。

修法：窗口宽 = **两列之和**（`PET_COL + BUBBLE_COL`），并用 `justify-content: end` 贴右。
这条写进 `closedWidth()` 的注释里了。

## ② 「靠近」不恢复待机：根因不是"事件丢了"，而是"判定太粗"

上一轮人家把根因判成"穿透态收不到 mousemove"，于是加了一条"每 250ms 问一次鼠标在哪"的兜底心跳。
**兜底本身没错，但真正的根因是另一件事**：

> 「靠近」的判定一直用的是**角色矩形**（167×200 的整块），而矩形的四个角、脸上的空隙、两腿之间**都是空气**。
> 鼠标从她身上往**下**或**往右**滑，只要还在这块矩形里，渲染层就一直认为"还在她身上" →
> `backToIdle()` 里那条"鼠标仍在角色上就停在 hover 最后一帧"的分支永远成立 → 动作就卡住不动了。
> （往左/往上滑很快出矩形，所以主人感觉"只有下/右有问题"。）

**修法：把"在她身上"改成逐像素判定**（`pointOnCharacter()`）：
把当前帧画布的 alpha 缓存成一张 Uint8 位图（每帧只算一次，24 帧 LRU），
鼠标位置映射到位图上一查就知道是不是实体像素。矩形只做粗筛，省掉大部分计算。

这样"往下滑动到腿边的空气里" = 立刻算离开 → 回待机。**事件路径和兜底心跳两条都换成逐像素判定**，
两者互为备份（事件断了兜底也能发现）。

### 自检里为此加的回归断言（含真机场景复现）

```
PASS  鼠标移入角色 → 切到「靠近」动作
PASS  鼠标移出 → 回到待机动作
PASS  鼠标靠近后往下移开 → 回到待机动作（事件断了也有兜底）
      移入点=(286,67)（角色身上的实体像素）→ hovering=true；
      移开点=(286,249)（角色下边界 +15px，且**故意不发 mousemove**）→ hovering=false 当前动作=idle；
      兜底心跳 运行2次 修正1次（逐像素位图 8316 个实体像素）
PASS  鼠标靠近后往右移开 → 回到待机动作（事件断了也有兜底）
```

那两条断言**故意不发 mousemove**：只把"主进程看到的鼠标位置"换成一个角色外的点，
逼着兜底心跳自己去发现 —— 这正是真机上"窗口切回穿透态、事件断掉"的场景。

写这两条断言时踩的坑（都记下来，免得下次再犯）：
1. 自检的"移入点"不能再用矩形中心：改成逐像素之后，中心可能正好是空气（脸上的空隙）→ 断言红。
   现在由渲染层从位图里扫出**第一个实体像素**再换算回坐标（`__petTest.solidPoint()`）。
2. 同理"移出点"要移到**真空气**上（`__petTest.emptyPoint()`），不能随便取 (1,0)。
3. 自检的假鼠标坐标**不能**用 `win.getBounds()`（Electron 逻辑像素）+ 渲染层 `window.screenX`
   （Chromium CSS 像素）凑出来 —— 150% DPI 下两者不是同一个数，凑出来的点会落在角色里，
   兜底判定永远 `inside=true`（人家第一版就这样白跑了两轮）。现在自检直接给**窗口内坐标**。
