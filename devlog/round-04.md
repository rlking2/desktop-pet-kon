# 第 4 轮：气泡不可见的真凶（人家自检工具造成的）

日期：第 4 轮开发（主人第三次反馈）
现象：左键点击没反应、右键菜单不出来。

## 破案过程（这次不靠推理，靠仪表）

主人第二次反馈时人家已经改了两轮、自检全绿，但真机还是不行。所以这轮**不再猜**，
先给桌宠装了"行车记录仪"：`artifacts/input-*.log` 记录**每一个真实鼠标事件**。

主人点完，人家读日志，结论直接翻转：

```
[00:32:15.692] mousedown  target=ellipse button=0
[00:32:15.696] click      target=ellipse button=0
[00:32:15.696] click-handler 气泡台词即将播放
```

**点击和右键在事件层面全部成功**（8 次 `click-handler`、4 次 `contextmenu` 送达渲染层）。
所以问题不在事件，而在**渲染/显示**。

顺着这条线做像素取证，抓到真凶。

## 真凶：一个不可撤销的 `insertCSS`

`lib/click-through.js` 的 `refreshMask()` 里，为了生成干净的穿透掩码，人家这样写：

```js
await win.webContents.insertCSS(
  '#bubble { visibility: hidden !important; }'   // 藏气泡
);
// ... 截图生成掩码 ...
return mask;   // ← 就返回了，这段 CSS 永远生效！
```

**`webContents.insertCSS()` 是没有返回值可以用来撤销的**（它返回的 key 只能配 `removeInsertedCSS`
用，而当时根本没保存）。于是：

> 生成掩码之后，`#bubble` 在整个会话里 `visibility: hidden`，
> **气泡永远不显示** —— 而点击处理器照跑、class 照加、`opacity` 计算值还是 1。

这就是"点了有反应但屏幕上什么都没看到"的完整解释。**而且这是人家的自检辅助代码造成的**，
主人从第 2 轮起就一直看不到气泡。

### 为什么人家的自检测不出来

人家的断言查的是 `classList.contains('show')` 和 `getComputedStyle(...).opacity`，
**`visibility` 根本不在检查范围内**。而且探针截图存下来人家也看不出来（模型没有图片输入能力）。

### 修法

改用"根元素临时 class + 可移除的 `<style>` 标签"，用完**立即还原**，并记录还原结果：

```js
document.documentElement.classList.add('pet-mask-freeze');
// 生成掩码
document.documentElement.classList.remove('pet-mask-freeze');
document.getElementById('__pet-mask-freeze-style')?.remove();
// 返回 { styleLeft, freezeClassLeft, bubbleVisibility } 供自检断言
```

并新增断言：
`生成掩码后气泡已恢复可见（不许用不可撤销的 insertCSS）`

### 新增的取证手段（以后不再"看不见"）

| 手段 | 作用 |
|---|---|
| `气泡真的可见（透明度≈1）` | class 加上 ≠ 看得见 |
| `气泡完整在窗口视口内` | 气泡被推出窗口也算"看不见" |
| **`截图里气泡区域确实被画出来了（像素证据）`** | **最终裁判：数气泡区域的不透明像素**（现为 99%~100%） |

## 顺带修掉的

1. **真实拖动尺寸漂移**：`realDrag` 每拖一次窗口 +1px（DPI 吸附）。
   修法：锁存设计尺寸 + **物理像素量化补偿**，让目标尺寸吸附回同一网格点。
   实测：真实拖动 3 轮 `201x251 → 201x251 → 201x251` 零漂移。
2. **右键兜底**：新增 Electron 原生 `webContents 'context-menu'` 路径（不经过 DOM），
   并给菜单加 600ms 去抖，避免 IPC 与原生路径双开。
3. **菜单栏把窗口撑高**：`setApplicationMenu` 会给无边框小窗加菜单栏（高度 250 → 255）。
   改成"设置菜单 + 立即隐藏"，既保留中文菜单和快捷键，又不占空间。
4. **调试红框被烧进穿透掩码**：`refreshMask` 忘了藏 `#dbg`，整圈边框变成"实体"。
   已修 + 新增断言 `掩码未把窗口边框当成实体`。

## 人家该记住的教训（本轮最重要的一条）

> **测试辅助代码本身会成为 bug 源。**
> `refreshMask()` 是为了让穿透更准才写的，结果它把气泡永久藏了起来，而人家的断言
> 又刚好不看 `visibility` —— "自检全绿"反而掩盖了真相。

配套原则：
1. **临时改动必须可撤销**，并且要**断言"已还原"**（不能只断言"设置成功"）
2. **"属性对了"不等于"用户看得见"**：视觉功能最终要用**像素证据**判
3. 真人反馈与自检结论冲突时，**先怀疑自检的盲区**，别急着改功能代码
