# 第 14 轮：待机 ↔ 开心对调 + 待机「只留人物」

主人的原话：**「去掉开心动作除人物外的所有彩色斑块，并把开心动作替换为待机动作，待机动作替换为开心动作」**。

## 一、人家是怎么理解这句话的

两句话、三个动作，顺序很重要（人家按这个顺序做的）：

1. **先把「开心动作」那张图里除人物外的彩色斑块清掉** —— 这里的"开心动作"指的是**当前**
   挂在开心上的那张定格图（就是主人上一轮发来的姿势图）。
2. **再把两组素材对调** —— 待机那三帧动画换成"开心"的，那张（已经清干净的）姿势图换成"待机"的。

为什么这么理解（而不是"先对调、再把新的开心清干净"）：**静止的图不该配"冻住的彩纸"**。
点「开心」是**保持住**的（点一次一直保持），要是一堆彩纸僵在她周围几十分钟，很怪；
而三帧动画**在动**，配上彩纸才好看。

于是最终状态：

| | 之前 | 现在 |
|---|---|---|
| **待机** | 3 帧动画（带彩纸、会动） | **1 张定格图**（只有人物，静止） |
| **开心** | 1 张定格图（带彩纸，保持住 = 冻住） | **3 帧动画**（带彩纸，循环播） |

> ⚠️ 如果主人本来想的是"对调之后，**新的开心**（也就是那三帧动画）也不要彩纸"，
> 说一声就行 —— 一条命令的事：`node scripts/keep-character-only.js --write happy`，
> 然后重新构建那两组。人家没有先做，是因为"静止图去彩纸、动画留彩纸"这版更像您想要的效果。

## 二、「只留人物」是怎么做的

新写了 `scripts/keep-character-only.js`：

```
连通块标记 → 只保留面积最大的那一块（人物本人），其余全部置透明
```

为什么不用"按颜色筛"：斑块有黄、橙、紫、红、粉、白好几种，按颜色写规则永远漏；
而"人物是一整块连通的"在这套素材上是成立的 —— 实测：

```
【人物·保留】 174933px  376x817
【彩色斑块·删】 11425px  124x123  avgRGB=219,188,88    ← 黄叶子
【彩色斑块·删】  5297px  117x 67  avgRGB=207,114,65    ← 橙叶子
【彩色斑块·删】  3120px   93x 43  avgRGB=119,104,130   ← 紫叶子
【彩色斑块·删】  1373px   48x 37  avgRGB=184,164,96    ← 黄花瓣
【彩色斑块·删】 607 / 589 / 579 / 481 / 462px           ← 五片小花瓣
→ 共清掉 9 块 / 23933 像素（人物那块不动）
```

工具默认只体检，`--write` 才写；素材有 git 记录，随时可回滚。
跑完人家把成品帧**合成到浅色底上看过**：确认只剩人物，头发/裙子/腿/鞋都完整。

## 三、顺手修掉两个之前漏掉的东西

### ① 粉色"水滴"没被清掉（第 13 轮的漏网之鱼）

第 13 轮清页面残留时，人家给"紧凑色块"加了个豁免（为了救回那片粉色叶子），
结果**把同形状的粉色水滴也豁免了** —— 它填充率 0.32 > 0.30，正好躲过判据。

改法两条：

1. 判据**顺序**调整：粉色线稿的判定放到"紧凑色块豁免"**前面**（先定罪再豁免）
2. 粉色的判据从 `B >= G-10` 收紧成 **`B > G`**（粉偏蓝、红褐偏黄）——
   这条才真正把"页码线稿/水滴"和"红褐色叶子"分开

重新体检后，`idle/frame-03`、`happy/frame-01`、`interact/frame-02` 里各揪出一块，
一共又清掉 **3 块 / 1501 像素**，同时粉色叶子照样保住了。

### ② 素材换帧数后，旧的成品帧会留在磁盘上

对调之后待机只剩 1 帧，但 `assets/build/frames/idle/` 里还躺着 `frame-001/002.png`
（清单里不引用它们，**不影响播放**，但目录看着像还有 3 帧，而且会被一起打进便携包）。

改法：`inspect-assets.js --write` 现在是**先清空该组的成品帧目录再写**。
重新构建后：`idle/` 1 个文件、`happy/` 3 个，便携包也从 372.0 MB 回到 370.8 MB。
