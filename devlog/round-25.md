# 第 25 轮：接入 API —— 别人装上桌宠之后，怎么用**自己的**大模型

主人的原话：**「对了，别人怎么接入API啊，是不是需要一个接入API接口的选项」**。

先回答"是不是需要一个选项"：**是，而且必须是一个正经的设置入口**。理由很实在 ——
别人下载的是**安装包**，密钥不可能跟包走（跟包走就等于把密钥公开了），
所以每个人得能自己填。没有设置入口 = 这个功能等于不存在。

问过主人三个选择题，答复是：**DeepSeek 为主（其他 OpenAI 兼容的也能填）** +
**独立的设置窗口** + **先做「设置 + 能对话 + 出错有话说」**。

## 做成了什么

| 位置 | 是什么 |
|---|---|
| 右键菜单 → **「设置…（接入 API）」** | 打开独立设置窗口（470×760，可缩放），不在桌宠那个透明窗口里 |
| 设置窗口 | 服务商预设（DeepSeek / OpenAI / Kimi / 通义 / 智谱 / **本地 Ollama**）+ 地址 + 密钥 + 模型 + 高级项 + **测试连接** |
| 待办面板底部 **「和她说…」** 一行 | 打字 → 回车 → 主进程发请求 → 回复落到头上的气泡（并顺手切「开心」动作） |
| 失败时 | **不弹报错框**，她用自己的口气说一句人话（8 类错误各有台词） |

## 三个关键设计决定（都是权衡过的）

### 1) 为什么放**独立窗口**，而不是塞进待办面板

桌宠那个窗口是 **200×250 的透明无边框窗 + 逐像素穿透掩码**。往里塞表单要同时改两样东西：
窗口尺寸（会推走"桌宠屏幕位置不能动"那条铁律）和穿透掩码（点不到输入框就等于没有）。
独立窗口是普通窗口：能缩放、能滚动、有正常焦点，也不用碰穿透逻辑。
**代价**：多了个窗口要管（关闭要置空引用、`resizable` 要留），但比改穿透便宜得多。

### 2) 为什么密钥**只走主进程**

渲染层是网页。网页里的东西（XSS、开发者工具里粘贴一段脚本）都可能读走密钥，而密钥被偷是要花钱的。
所以定死三条：

1. 密钥只存在主进程内存 + `%APPDATA%\dsh-desktop-pet\api-config.json`（`mode 0600`）；
2. IPC **只进不出**：`apiConfigSave` 往里写，`apiConfigGet` 回的是 `publicView()` —— 
   只有 `hasKey` / `maskedKey`（`sk-abc••••••••wxyz`）/ 地址 / 模型；
3. 自检里有一条断言专门盯这件事（**密钥不会出现在发给渲染层的任何东西里**）。

顺带说清楚**渲染层本来也发不出去请求**：`renderer/index.html` 的 CSP 是 `default-src 'none'`。
API 调用走 Node 的 `http/https` 模块（`lib/chat.js`），跟渲染层完全无关 ——
这也是为什么"接入 API"不需要放宽 CSP。

### 3) 为什么错误都要翻译成台词

桌宠的对话框是主人天天看的地方。超时了弹一句 `TypeError: fetch failed`，
这东西立刻从"桌宠"变成"报错框"。所以 `lib/chat.js` 里 `classify()` 把
401/402/429/404/5xx/超时/DNS 失败/连不上 全部映射成她自己的口气，
技术细节（HTTP 状态、错误正文）只写进 `artifacts/input-*.log`。

还有一条**降级**：有的网关不接受多轮上下文（HTTP 400），这时**自动退回单轮重试一次**，
而不是直接告诉主人"对面回的话人家看不懂"。

## 踩到的坑

### 坑 1：面板放不下了（一行输入框顶掉一栏待办）

待办面板原来固定 130px 高（5 栏），加一行「和她说…」后自然高度 251px，
而窗口只有 250px → 面板顶边跑到 **-1**，被窗口裁掉（自检"面板完整在窗口内"当场红）。

第一次人家按"砍一栏"算成 103px，结果**还是 245px**，还是裁。
→ 改用**量出来的数**：临时写了个探针把每个子元素的高度打出来
（head 13.6 / 输入 27.8 / 滚动 / 页脚 12.6 / 分隔 12.3 / 对话输入 25.9 / 间距 5×6 / 内边距 16），
倒推出窗口能给的**面板天花板 = 250 - 6×2 = 238px** → 滚动区必须 ≤ **88px**（约 3 行半）。
**教训**：这种"差几像素就裁掉"的事，不许靠估，必须量。

### 坑 2：断言"因为元素不可见反而通过"

查「和她说…」输入框那条断言，一开始在**面板收起**的时候量 —— 
`display:none` 的元素 `getBoundingClientRect()` 全是 0，于是 `0 >= -1 && 0 <= 1` 成立，
**假绿**。改成"先展开面板再量"，并且把尺寸一起断言（宽 > 100 且高 ≥ 20），
顺便还查出断言顺序排在面板收起之后这件事。

### 坑 3：错误分类的两种返回形状不一致

`classify()` 返回 `{ kind, line }`，`chat()` 返回 `{ ok, kind, text }`。
自检里混着用，结果 6 条"漏了"。→ 加了一个 `lineOf()` 统一取，
顺带在代码里把签名写清楚（`classify(网络错误, HTTP 状态, 响应正文)`）。

### 坑 4：设置窗口的按钮被挤到看不见的地方

第一次设 640 高：在 150% DPI 下视口只有 **456×658**，而内容 783px →
「保存 / 测试连接 / 状态 / 配置路径」全在折叠线以下。主人点开设置第一眼看不到"保存"，会以为坏了。
→ 压排版（字号/间距/状态条高度）+ 窗口提到 760（视口 698），实测内容 669px，**一次不用滚动**全看得见。
