# 第 26 轮：回复气泡不许和提问面板挤在同一侧

主人的原话：**「跟她聊天的时候，回复与提问窗口总在同一侧，需要你改成识别提问窗口自动把回答生成在另一侧」**。

现象解释：面板展开时窗口内部是两列 `[面板][桌宠]`，而气泡的 CSS 一直是"整窗居中（`left:50%`）"——
它正好骑在两列的接缝上，看起来就是**回复压在提问框上**。

## 结论先说：不是"把气泡推走"，而是"给气泡一列"

这是本轮最大的教训。人家试了三版才对，把三版都记下来：

| 版本 | 做法 | 结果 |
|---|---|---|
| ❌ 第一版 | 算出偏移量，把气泡**推到面板左边** | 气泡被推到 **-42px**，直接跑出窗口（窗口只有 200 宽，气泡 192 宽）→ 自检红 |
| ❌ 第二版 | 把窗口**加宽**一个"气泡列"，但 CSS 网格还是两列 | 多出来的宽度被 grid 摊到别处 → **桌宠在开关面板时跳了 461px** → 自检红 |
| ✅ 第三版 | 窗口**三列** `[气泡列][面板列][桌宠列]`，两种状态列宽完全一致，气泡用 CSS 住在气泡列里 | 桌宠偏移 **0px**、气泡偏移 **0px**、气泡与面板间隙 **51px**，全绿 |

## 为了让它成立，改了这些（都是被自检逼出来的）

1. **窗口宽度两种状态一样**（≈660px，收起时左边两列是空的）。
   为什么：宽度一变，`justify-content` 把余量塞到左边 → 列整体平移 → 画面跳。
   代价写在 README 已知限制里：窗口比看得见的部分宽，但那部分是透明 + 逐像素穿透的，不影响桌面。
2. **网格显式写列号**，抛弃 `grid-template-areas`。
   原因：areas 和 auto-placement 混用，收起态（面板 `display:none` 退出布局）时剩下的元素会被**自动补位**到前面的列——
   实测桌宠从第 3 列跳到第 1 列（偏移 461px）。
3. **`--panel-right` 语义曾经是反的**：`side==='right'`（面板在右 = 默认布局）却加了 `panel-right` 类，
   把桌宠换到了最左列 → 偏移 341px。现在改成 `side==='left'` 才加，并把命名含义写进注释。
4. **桌宠列 / 气泡列宽度都改成"实测回报"**：
   - 气泡列：渲染层临时量一次气泡的真实布局宽度（`position:static` + 一帧后撤回），回报给主进程；
   - 桌宠列：回报 `--sprite-w`（sprite 显示宽度）。⚠️ 不能量 `getComputedStyle().gridTemplateColumns`——
     它会把 `var()` **原样吐回来**（实测 "163px 300px 130px" 合计 593 而视口 630，看着像错位，其实布局是对的）。
     这条坑写在自检断言的注释里：**判列宽只信真实矩形**。
5. **桌宠改成 `justify-self: end` 且 margin 归零**：窗口右边界 = 桌宠列右边界，
   于是"窗口右边界不动"就等于"桌宠屏幕位置不动"，主进程的锚点算法才成立。
   锚点算法也重写了：不再"基于当前 bounds 推"，而是 `窗口右边 - 需要的宽度`，屏幕放不下时夹进工作区。
6. **气泡的 CSS 从"整窗居中"改成"住在气泡列里"**（`left:8px; right:calc(100% - var(--bubble-w) + 8px)`），
   而且**收起态也走这套定位** —— 否则开关面板时气泡会从居中跳到列里（实测跳 248px）。

### 最后 1px 的坑：`.flip` 里的老 `translate(-50%, 0)`

气泡贴屏幕顶部时会翻到角色下方（`.scene.flip`）。那条老规则里带着 `translate(-50%, 0)`，
在新的 `left/right` 定位下等于**又被推走半个气泡宽** → 气泡跑到 -77px，直接出窗口。
自检的"气泡左边界 ≥ 0"当场抓到。**教训**：改定位方式时，要把所有"顺带也设了 transform"的老规则一起清掉。

PASS  ★气泡在开关面板时也不左右跳（气泡列宽度固定）  气泡左边界 21 → 21，偏移 0px
