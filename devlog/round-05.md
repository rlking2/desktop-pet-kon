# 第 5 轮：帧动画素材管线（人家看不见图，所以把活全交给程序）

日期：第 5 轮开发
主人诉求：「可以识别动图吗，模板帧数比较难截」+ 选了「散帧 PNG/精灵图 + 渲染层循环播放」

## 先把能力边界说清楚

**人家看不了动图，也看不了静态图** —— 当前模型 `deepseek-v4-flash` 不支持图片输入。
所以这一轮的思路不是"让人家看图"，而是：

> **把"需要眼睛"的部分（挑帧、审美）留给主人，
> 把"纯机械"的部分（拆帧、对齐、计时、校验）全部程序化。**

主人不需要手截帧了。

## 交付

| 文件 | 作用 |
|---|---|
| `scripts/inspect-assets.js` | **核心**：零依赖 PNG 解码 + 素材体检 + 自动对齐 + 生成清单 |
| `lib/assets.js` | 主进程侧读取清单（避开渲染层 CSP 对 fetch 的限制） |
| `renderer/renderer.js` | 帧动画播放器（rAF 按每帧延时推进，等比铺满画布） |
| `renderer/index.html` + `style.css` | 新增 `#sprite` 画布；有素材切 canvas，无素材显示内置 SVG |
| `scripts/make-test-assets.js` | 生成合成测试素材（验证流水线用，产物在 `_fixtures/`） |
| `assets/README.md` | 主人视角的使用说明 |

## 支持两种素材形态

1. **散帧序列** `assets/<动作名>/*.png`（按文件名自然排序）
2. **精灵图** `assets/<动作名>.png` + 同名 `.json`（cols/rows/frameWidth/frameHeight）

多动作组会自动合并进 `assets/manifest.json`，运行时只读这一份。

## 体检会拦下的问题（都是会让桌宠"看起来坏掉"的坑）

| 检出项 | 后果 |
|---|---|
| PNG 没有 alpha 通道 | 桌宠变成方块，还挡住鼠标穿透 |
| 背景没抠干净（整帧几乎不透明） | 白底跟着显示 |
| 有帧几乎是空的 | 动画会闪 |
| 帧尺寸不一致 | 警告 + 自动对齐 |
| 帧间主体面积波动过大 | 警告：可能把不同动作混进一组 |

**为什么不做自动抠图**：抠图需要判断"什么是背景、什么是角色"，这需要眼睛。
人家看不见图，硬做只会把角色也抠掉。所以这一步老实交给主人用在线工具处理。

## 自动对齐怎么做的

以每帧的**主体包围盒**为准：把 alpha 通道里"不透明像素的最小外接矩形"算出来，
再按这个矩形把主体贴到统一画布的中心。

好处：主人从网上截的帧通常**四周留白不一致**（有的偏左、有的偏下），
直接放会产生"角色每帧都在抖"的效果；按包围盒对齐能消掉这种抖动。

## 验证（不靠眼睛，靠数据）

用合成素材做了对照实验：

```
散帧序列 8 帧         → 识别为「_fixtures/idle」，8 帧，统一画布 71x71
精灵图 4x2            → 识别为「_fixtures/sheet」，8 帧，单帧 96x96 正确切分
故意做坏的 4 帧       → FAIL：3 帧几乎整帧不透明（白底没抠）、1 帧几乎是空的
```

接入运行时后的双模式自检：

| 场景 | 自检 | 像素分析 |
|---|---|---|
| 有素材（sprite-mode） | 50/50 ✅ | 5/5 ✅（自动跳过 SVG 专属色卡断言） |
| 无素材（退回 SVG） | 50/50 ✅ | 11/11 ✅ |

## 踩到的坑（人家的低级错误）

1. **PNG 注释用了 `//`** —— PowerShell 脚本里 `//` 不是注释，导致解析失败。
   好在这次是自己的测试脚本，主人没受影响。
2. **产物被自己的扫描器当成新素材** —— 对齐帧原本写在 `assets/<组>/aligned/`，
   下次扫描又把 `aligned` 认成一个新组。改成写到 `assets/build/`（扫描器跳过该目录）。
3. **分组规则想当然** —— 一开始只看"目录里直接放的 png"，把精灵图误判成单帧序列。
   改成"先认精灵图（png+同名 json），再收散帧序列"。
4. **体检判据太弱** —— 只查"纯白满像素"，而白底图其实是 240,240,240 这种近似白，
   于是漏检。改成查"alpha≥16 的像素占比 > 0.97"（整帧几乎不透明）。

## 人家仍然做不到的（照实说）

1. **看不出图里画的是什么**：主人给人家一只鲸鱼娘的 GIF，人家只能说"8 帧、每帧 128x128、
   第 3 帧主体比别的帧小 20%"，**说不出"第 3 帧画得丑"**。
2. **挑不出好看的帧**：审美必须主人来。
3. **帧率要主人定**：人家默认 120ms/帧，快慢得主人说。

## 主人下一步

把 PNG 丢进 `assets\<动作名>\`，然后：

```powershell
npm run assets:write    # 体检 + 生成对齐帧与清单
npm start               # 自动播放帧动画
```

没有清单时会自动退回现在的内置 SVG 形象，不会白屏。
