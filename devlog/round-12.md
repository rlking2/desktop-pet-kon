# 第 12 轮：去掉「靠近时底下那行白色提示」

主人的原话：**「靠近后底下提示白字"按住拖我走，右键有菜单"去掉」**。

## 改了什么

| 位置 | 之前 | 现在 |
|---|---|---|
| `renderer/index.html` | `.pet` 里有个 `<div class="hint">按住拖我走 · 右键有菜单</div>` | **整个元素删掉** |
| `renderer/style.css` | `.hint {…}` + `.pet:hover .hint { opacity: .95 }` | **样式一起删掉**（只留一段说明，免得以后有人只删 HTML 留一条死规则） |
| `renderer/index.html` | `.pet` 上有 `title="按住拖动"` | **也删了** —— 那是浏览器/系统的原生悬浮提示，鼠标停一会儿就会蹦出来，同样属于"靠近时的提示" |

顺带一个**意外的好处**：`.pet` 原来 = 画布 200px + 提示那一截约 15px，
而 `setHover()` 的判定用的就是这个矩形 —— 也就是说**贴着角色下边缘的那条空白，原来也算"靠近"**。
现在命中区正好等于角色本身（自检实测 `150x200`）：

```
改前: petRect={"x":48,"y":23,"w":150,"h":215}
改后: petRect={"x":48,"y":38,"w":150,"h":200}   ← 正好是 canvas 的尺寸
```

角色在窗口里因此**下移了 15px**（`.pet` 是 `align-self: end` 贴底布局）。
这属于正常位置变化：穿透掩码是按像素重算的，几何/位置相关断言全部照过（见下）。

## 自检：97 → **98/98 ✅**

新加一条**反向断言**，专门盯着"别再被加回来"：

```
PASS  靠近时不再有任何提示文字/提示气泡（主人要求去掉）
      (.hint 元素存在=false；#pet 的 title=（无）；命中区 150x200（正好等于角色本身，不再多出提示那一截）)
```

> 经验：**删 UI 的时候顺手加一条"它不该存在"的断言**，比只删代码可靠 ——
> 这个项目里 `.hint` 是第 1 轮为了"窗口底边溢出"调整过的元素，
> 说明它会被人反复碰；不写反向断言，下次很容易又冒出来。

其余 97 条（含几何、穿透掩码、靠近动作、保持动作、菜单）**全部照过**：

```

PASS  掩码未把窗口边框当成实体
PASS  鼠标移入角色 → 切到「靠近」动作
```
