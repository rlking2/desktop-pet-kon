## 这一轮真正的收获：把 CSS 网格整个撤掉

前两轮（26/27）反复翻车的根因，这一轮终于查清楚了：

> **`position: absolute` 的子元素，它的包含块是"网格区域"，不是整个网格容器。**

也就是说：面板写了 `position:absolute; left:6px`，但它同时是网格 item、又被指定了 `grid-column: 2`，
于是它被"锁"在第 2 格里 —— 实测 `style.left = 6px`、`getComputedStyle().left = 6px`，
而 **`offsetLeft = 380`**、`getBoundingClientRect().left = 380`。
所以人家怎么改 `left` 都钉不到窗口左边，气泡自然也躲不开它。

**修法：`.scene` 从 `display: grid` 改成 `position: relative`**，三个东西全部绝对定位：

| 东西 | 位置 | 谁决定 |
|---|---|---|
| 人物 | 窗口**右下角**（`right:0; bottom:0`） | CSS |
| 面板 | 打开时窗口**左边**（`left:6px; bottom:6px`） | CSS（`.memo` 绝对定位，不再受网格约束） |
| 气泡 | 收起时她**左上角**；面板打开时她**右上角** | renderer.js 的 `relayoutBubble()` 按她的真实矩形算 |

窗口宽度也跟着简化：`closedWidth = 人物列 + 气泡段`，`openWidth = 面板 + 人物列 + 气泡段 + 人物列 + 8`
（展开态人物右边也要留出气泡那一截）。不再要求"窗口宽必须等于某几列之和"——
那条约束就是 26/27 轮反复翻车的另一半原因。

`relayoutBubble()` 还是把气泡**夹在窗口内**（横轴、纵轴都夹）：素材换帧、她往上冒一点时，
气泡不许跟着跑出窗口（实测被推到 -75px 那种）。
